# 포트폴리오 프로젝트 카드 재구성 디자인 스펙

날짜: 2026-10-27 · 상태: 사용자 승인 완료 (구현 전)
대상 리포: `hollyriver.github.io`
상위 스펙: [2026-08-12-portfolio-design.md](2026-08-12-portfolio-design.md)

## 문제

현재 Featured Projects 카드의 세 가지 불만.

1. **구도가 난잡하다** — 펼친 본문이 `문제 · 접근 · 엔지니어링 · 역할/현황` 4항목으로 빽빽하고, 제목 줄은 뱃지를 오른쪽 끝으로 밀어내느라 `padding-right: 84px`를 먹어 자주 줄바꿈된다.
2. **문장이 늘어진다** — 한 항목이 3~4줄짜리 한 문장인 경우가 많아 읽는 속도가 느리다.
3. **시각 자료가 없다** — 모델·파이프라인 구조를 글로만 설명해 한눈에 들어오지 않는다.

## 결정

### 범위

**SurvLLM 카드 하나만 재구성한다.** 나머지 세 카드(LLMdetector · TSTF · NYCTaxiDash)와 다른 섹션(About, Publications, Skills, Education, Footer)은 내용·구조 모두 손대지 않는다.

근거: 그림이 준비된 프로젝트가 SurvLLM 하나뿐. 나머지는 그림을 만드는 시점에 같은 틀로 순차 전환한다. 이번 작업의 CSS는 그 전환을 염두에 두고 범용으로 작성한다.

예외는 제목 줄 정리 한 가지 — CSS 한 곳의 변경이고 카드 간 줄맞춤이 어긋나면 오히려 난잡해지므로 **네 카드 전체에 적용**한다. 나머지 세 카드의 HTML 문구는 그대로다.

### 카드 레이아웃 (3안 중 A안 채택)

브라우저 시안으로 세 안을 비교해 A안 확정.

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 펼쳤을 때 이미지** | 접힌 목록은 제목+한 줄 요약, 클릭하면 이미지+본문 | **채택.** 인쇄 PDF가 제출 기준인데 인쇄본은 어차피 전부 펼쳐지므로 손실이 없고, 웹에서는 목록이 짧아 4개 프로젝트가 한 화면에 들어온다 |
| B. 접힌 상태에도 썸네일 | 목록 좌측에 작은 그림 | 기각. "한눈에"는 가장 강하지만 목록이 길어지고, 그림 없는 카드가 섞이면 높이가 들쭉날쭉해진다 |
| C. 접기 없이 항상 펼침 | 아코디언 제거 | 기각. 구도는 가장 단순해지지만 스크롤이 길어진다 |

### 카드 본문 구성

항목을 **개요 · 기여 2개로 한정**한다. "이 프로젝트가 무엇인가"와 "거기서 내가 무엇을 했는가"만 남긴다.

```
┌ summary ─────────────────────────────────┐
│ 제목 [뱃지]                      접기 ▴  │
│ 한 줄 요약                               │
├ body ────────────────────────────────────┤
│ [ figure/SurvLLM.png — 전폭 ]            │
│ 캡션 한 줄                               │
│                                          │
│ 개요                                     │
│   한 줄 정의                             │
│   ① Phase 1 — 무엇을 하는 단계인가       │
│   ② Phase 2 — 무엇을 하는 단계인가       │
│ 기여                                     │
│   전체 중 내가 담당한 범위               │
│                                          │
│ [기술 태그]  GitHub                      │
└──────────────────────────────────────────┘
```

- **개요**: 한 줄 정의 뒤에 번호칩이 붙은 Phase 2줄. 번호는 `figure/SurvLLM.png` 안의 ①② 박스와 일치시켜, 그림과 글이 서로를 가리키게 한다.
- **기여**: Phase 1 전면 담당이라는 사실과 그 범위.
- 기존 `엔지니어링` 항목의 세부(FSDP-QLoRA, 프롬프트 구조, JSON 검증 로직)는 개요·기여로 흡수하거나 덜어낸다. 상세는 리포 README가 담당한다.

### 문체

**명사형 종결**을 기본으로 하고, 한 문장을 1~2줄로 끊는다. (예: "…수작업 정리가 불가능", "…단독 수행", "…평가 진행 중")

### 제목 줄 정리

`.card-head`의 `justify-content: space-between`을 제거해 뱃지를 제목 바로 뒤에 붙이고, 오른쪽 여백을 `84px → 54px`로 줄인다. 절대 배치된 `.hint`("자세히 ▾")와의 충돌을 피하려 넓게 잡아 둔 여백이 원인이었다.

### 신규 CSS

다음 카드에 그림을 넣을 때 HTML 한 덩어리만 추가하면 되도록 범용으로 작성한다.

- `figure.fig` / `figure.fig img` / `figcaption` — 전폭 이미지와 캡션
- `.phase` / `.pnum` — 번호칩이 붙은 단계 설명 줄

## 문구 (임시)

사용자가 직접 다듬을 예정이므로 현재 내용에 맞춘 초안으로 넣는다.

- **한 줄 요약**: 퇴원요약지를 생존분석용 임상 변수로 바꾸는 LLM 사후학습 파이프라인 — 텍스트 규격화 단계 단독 구축
- **캡션**: 퇴원요약지 → 규격화 문장 → 생존함수
- **개요**: 비정형 퇴원요약지에서 생존분석용 임상 변수를 추출하는 2단계 파이프라인. 한 건이 최대 3만 토큰에 달해 수작업 정리가 불가능
  - ① **텍스트 규격화** — Llama-3.1-8B를 QLoRA로 SFT하고 DPO·PPO로 정렬, 제각각인 퇴원요약지를 고정된 문장 틀로 변환
  - ② **생존분석** — 규격화 문장을 SurvLIFT(Llama-3.2-1B)에 입력하여 생존함수 Ŝ(t) 추정
- **기여**: Phase 1 전면 담당. 데이터 구축, SFT, 선호도 레이블링(200건 중 130건 직접), DPO와 RM+PPO 두 경로 구현을 단독 수행. 규격화 문장을 15개 임상 피쳐로 파싱해 Phase 2에 전달. 현재 c-index 평가 진행 중

기술 태그와 GitHub 링크는 현행 유지.

## 인쇄 영향

- 이미지에 `break-inside: avoid`를 걸어 페이지 경계에서 잘리지 않게 한다.
- SurvLLM 카드는 현재 `break-inside: auto`(첫 카드 예외)이므로 카드 자체는 페이지를 넘겨 분할될 수 있다. 그림만 통째로 유지되면 된다.
- 항목이 4개→2개로 줄어 **분량이 감소**하므로, 2026-08-22에 고아 줄 방지용으로 숨긴 footer(`@media print { .foot { display: none } }`)를 원복할 수 있는지 `.debug/measure-print.mjs` 실측으로 판단한다. 페이지 수 정책은 상위 스펙을 따른다 — N페이지 고정이 목표가 아니라 몇 줄짜리 꼬리가 새 페이지로 밀리는 것을 막는 것이 기준.

## 반응형

이미지가 가로로 긴 다이어그램(1063×265, 약 4:1)이라 좁은 화면에서는 글씨가 작아진다. 이미지를 `<a href="figure/SurvLLM.png">`로 감싸 새 탭에서 원본 크기로 볼 수 있게 한다. JS 없이 해결된다. 인쇄 시 URL을 병기하는 규칙은 `.links a` · `.pubs a`만 대상으로 하므로 figure 내부 링크에는 영향이 없다.

## 제외 사항 (YAGNI)

- 나머지 세 카드의 재구성 — 그림이 준비되는 시점에 순차 진행
- 라이트박스·캐러셀 등 이미지 뷰어 — 새 탭 링크로 충분
- 이미지 포맷 최적화(WebP 변환, srcset) — 현재 35KB로 문제없음
- 다크 모드 — 상위 스펙 범위 밖

## 검증 기준 (완료 정의)

- SurvLLM 카드가 이미지 → 개요(Phase 1·2) → 기여 순으로 렌더되고, 번호칩이 그림의 ①②와 일치
- 나머지 세 카드의 HTML 문구가 제목 줄 CSS 변경 외에는 diff에 나타나지 않음
- 제목 줄이 데스크탑 760px 폭에서 줄바꿈 없이 한 줄에 들어감
- 모바일(360px)에서 이미지가 가로 넘침 없이 표시되고, 탭하면 원본이 열림
- 인쇄 미리보기(A4)에서 이미지가 페이지 경계에 걸리지 않고, 고아 줄이 생기지 않음 — `.debug/measure-print.mjs` 실측으로 확인
